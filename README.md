# IA-CARS · Vehicle Intelligence

«Цифровая медицинская карта автомобиля»: единый профиль машины, собирающий данные из VIN-баз, документов (OCR + AI), истории обслуживания, пробегов и расходов.

Монорепозиторий: NestJS-бэкенд в корне, фронтенд CARA — в `frontend/`.

## Стек

- **Backend:** NestJS 10, TypeScript (strict), Drizzle ORM + PostgreSQL (Neon), JWT + bcrypt, @nestjs/throttler, AWS S3-совместимое хранилище (Backblaze B2), pdfjs-dist + @napi-rs/canvas (рендер PDF), Groq (LLM/Vision) через AI Gateway.
- **Frontend:** Vite + React 19 (`frontend/`).

## Быстрый старт

```bash
npm install
cd frontend && npm install && cd ..

cp .env.example .env   # заполнить DATABASE_URL, JWT_SECRET, GROQ_API_KEY, B2_*, VIN_PROVIDER_API_KEY

npm run db:migrate     # применить миграции Drizzle
npm run start:dev      # бэкенд на http://localhost:3000
npm run dev:web        # фронтенд на http://localhost:5173
```

Проверка здоровья: `GET /health` (база + объектное хранилище).

## Внешние источники

Провайдер Vehicle Databases (`x-authkey`):

- Europe VIN Decode: `GET https://api.vehicledatabases.com/europe-vin-decode/v2/{vin}` — основной декодер (env `VIN_PROVIDER_URL`, `VIN_PROVIDER_API_KEY`).
- Advanced VIN Decode: `.../advanced-vin-decode/v2/{vin}` (env `ADVANCED_VIN_PROVIDER_URL` — опциональный оверрайд).
- Vehicle history: URL задаётся `VEHICLE_HISTORY_PROVIDER_URL`.

Результаты не сваливаются в один JSON: каждый источник нормализуется в свою сущность (спецификации → VehicleProfile, аукционы/продажи → VehicleHistory, пробеги → Mileage), а сырой ответ всегда сохраняется в `vehicle_external_reports`.

Каталог VIN-источников Vehicle Databases:

```
GET  /vehicles/:vehicleId/external-reports/sources          # каталог источников
POST /vehicles/:vehicleId/external-reports/sources          # закрыт: HTTP 400, без вызовов баз
POST /vehicles/:vehicleId/external-reports/sources/:source  # один источник
GET  /vehicles/:vehicleId/external-reports?type=<source>    # сохранённые отчёты
```

Статусы отчётов: `success` (есть данные), `no-data` (upstream: «Record(s) were not found»), `failed` (ошибка запроса, сохраняется с описанием).

### Один Бесплатный VIN-Запрос

`GET /vin-access` с JWT возвращает `state`, `freeRemaining` и `paidEnabled: false`.
На аккаунт доступен один запрос к одному VIN-источнику, общий для всех машин,
сайта и Telegram. Декодирование VIN, OneAuto и отдельная история автомобиля
используют тот же серверный лимит. После использования сервер возвращает HTTP
402 (`VIN_TRIAL_USED`). Массовый запрос отключён. Вопросы AI, ручные записи,
чтение сохранённых результатов и не-VIN-поиск CEPiK не расходуют этот лимит.

Перед вызовом базы сайт и бот показывают подтверждение. Результат `no-data`
тоже использует запрос и не означает, что история автомобиля чистая.
Ответ на VIN, отправленный прямо в Telegram, сохраняется в аккаунте, включая
результат `no-data`. На сайте он виден в «Отчётах» даже без добавления машины;
`GET /vin/checks` с JWT читает только результаты владельца без вызова базы.
При привязке Telegram эти результаты переносятся в основной аккаунт.
Помощник получает краткие сохранённые результаты без повторного запроса к
базе и без передачи сырого JSON в AI; он должен сверять VIN, прежде чем
относить найденные факты к выбранной машине.
Добавление машины, включая `/addcar`, не запускает проверку автоматически.
Платежи, цены и повторные платные проверки пока намеренно не подключены.

Резервирование в PostgreSQL выполняется до внешнего вызова и исключает два
одновременных запроса. Отсутствие конфигурации и явный отказ в авторизации,
квоте или частоте освобождают резерв. Тайм-аут, неоднозначный ответ, ошибка
сохранения и прерванный запрос оставляют доступ закрытым (`uncertain`, HTTP
409), без автоматического повтора. Истёкший десятиминутный резерв также не
выдаёт новую попытку. Для ручной сверки сохраняются аккаунт, VIN, источник и
время запроса. Публичного сброса лимита нет; сначала нужно сверить результат
с сохранёнными отчётами и журналом провайдера.

При привязке Telegram использование переносится в основной аккаунт, а старый
автоаккаунт больше не может воспользоваться бесплатной проверкой по старому
JWT. Привязка при незавершённой или неопределённой проверке отклоняется.
Миграция `0023_vin_check_access` учитывает прежние сохранённые успешные VIN-
проверки и результаты `no-data`; старые несохранённые standalone-запросы
Telegram восстановить задним числом нельзя.

### Образ Каждой Машины

Общий робот из `hero.webp`/`robot.webp` больше не используется интерфейсом.
Главная и аватары помощника показывают процедурный 3D-образ: устойчивый ID
машины определяет индивидуальные детали, подтверждённые кузов и цвет профиля
меняют форму и окраску. Это художественный аватар, не точная заводская модель
авто. При отсутствии профиля используются устойчивые художественные варианты,
а не выдуманные технические характеристики. Платные генераторы не вызываются.
Three.js загружается отдельно, миниатюры кешируются, анимация учитывает режим
уменьшения движения; без WebGL отображается индивидуальный буквенный значок.

Локальные проверки: `scripts/check-vin-transformers.cjs` (Playwright, desktop
и mobile, пиксели canvas, смена машины, перезагрузка, подтверждение и блокировка)
и `test/vin-access.test.cjs` (настоящие сервисы, JWT HTTP и изолированная PostgreSQL).

Проверка зависимостей frontend: Vite обновлён в пределах 6.x до 6.4.5,
source-map-js до 1.2.2; `npm --prefix frontend audit` не обнаруживает известных
уязвимостей. 3D-модуль загружается отдельным чанком (около 136 КБ gzip);
предупреждение сборщика о размере чанка остаётся информационным.

## Детект аномалий пробега

```
GET  /vehicles/:vehicleId/mileage/anomalies   # анализ сохранённых показаний
```

Анализирует хронологию показаний и находит: `rollback` (пробег со временем уменьшился — признак скрутки одометра; `severity: critical` при падении ≥ 100 км) и `implausible_jump` (средний прирост > 2000 км/сутки — вероятная ошибка данных). Ответ: `{ vehicleId, readingsAnalyzed, anomalies[] }`.

Запись показаний: для пользовательских источников (`manual`/`web`/`telegram` и т.п.) уменьшение пробега относительно сохранённого максимума отклоняется (защита от опечаток). Внешние исторические источники (`vdb:*`) сохраняются как есть — даже если показывают меньший пробег, — чтобы детект мог найти откат по всей хронологии.

## Общая память помощника

Сайт и связанный Telegram-аккаунт используют серверную историю по автомобилю
и языку: до 24 сообщений, каждое доступно не более семи дней. Кнопка очистки
в чате и команда `/forget` очищают этот чат в обоих каналах, но не удаляют
автомобили, напоминания и настройки. Генерации и подтверждения старого
поколения истории после очистки не принимаются.

На странице настроек доступны подробность ответа, приоритет владельца и тип
поездок. Они меняют инструкции помощника в обоих каналах; сроки ТО и правила
безопасности не меняются автоматически.

```text
GET    /assistant/history?vehicleId=<uuid>&language=uk
DELETE /assistant/history?vehicleId=<uuid>&language=uk
GET    /assistant/preferences
PATCH  /assistant/preferences
POST   /assistant/chat
```

Все маршруты требуют JWT. Владение автомобилем проверяется сервером.
В `/assistant/chat` новый клиент передаёт `expectedMemoryEpoch` из истории,
при сохранении настроек передаётся `expectedRevision`. Устаревшее состояние
даёт HTTP 409; перед повторением нужно перечитать данные.

Перед публикацией нового API примените миграции `0021_assistant_memory`,
`0022_assistant_preferences` и `0023_vin_check_access` штатной командой `npm run db:migrate` в целевом
окружении. Изменения frontend и API должны публиковаться согласованно.
Рабочая БД и платные провайдеры не нужны для `npm test`; сквозная локальная
проверка находится в `scripts/check-assistant-memory.cjs` и использует
Playwright, изолированную PostgreSQL и подставные AI/Telegram-транспорты.

## Деплой

**Один origin (Render).** Бэкенд сам раздаёт собранный фронт из `frontend/dist`
(`src/main.ts`). Перед деплоем выполните `npm run build:web`, затем обычный деплой API —
сайт и API будут на одном адресе без CORS.

**Два origin (Vercel + Render).** Корневой `vercel.json` собирает `frontend/`
(`npm --prefix frontend ci && npm --prefix frontend run build`) и публикует `frontend/dist`,
поэтому Vercel-проект может указывать на корень репозитория. В окружении Vercel задайте
`VITE_API_URL=https://vehicle-intelligence-o9mi.onrender.com`. Бэкенд разрешает origin
Vercel через CORS (по умолчанию в списке `https://vehicle-intelligence-nu.vercel.app`,
переопределяется `CORS_ORIGINS`).

В dev-режиме фронт ходит в API через vite-proxy (`frontend/vite.config.ts`), поэтому
`VITE_API_URL` локально не нужен.
